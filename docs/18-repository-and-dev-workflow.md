# 18 — Repository and Development Workflow

Product terminology: **Workspace = connection** to a server/host; **Project = git-friendly folder** of saved queries and API collections, opened via **Open Project Folder** with `.openrows/project.yaml`. Cargo/pnpm “workspace” below is the build-tool term.

## 2. Tooling

| Tool | Purpose |
| --- | --- |
| `rustup`, Rust 1.94.0 (`rust-toolchain.toml`), edition 2024 | Pinned compiler, rustfmt and Clippy |
| `cargo-nextest` | Isolated Rust unit test runs |
| `cargo-deny` | Dependency licences, advisories, bans and sources |
| `cargo-machete` | Unused dependency detection |
| Node.js >=24, pnpm 12.9.1 | Locked private workspace dependencies; exact pnpm checked by setup |
| TypeScript, ESLint 9, Prettier | Strict type checking, type-aware lint/limits, formatting |
| Vite, React 19 + React Compiler | Desktop frontend bundle and hot reload |
| Tauri 2, tauri-specta / Specta | Native shell and generated TypeScript commands |
| Vitest, Testing Library, Knip | Component/gallery accessibility tests and unused-code scan |
| Python 3 (standard library) | macOS startup/memory harnesses and headless benchmark tests |
| `just` | One-command quality gate (`just check`) |
| `sccache` (optional) | Compiler cache; set `RUSTC_WRAPPER=sccache`; sandbox behaviour in §2.2 |
| `scripts/git-hooks` | Git hooks enabled by `just setup`; currently `commit-msg` |

See [CONTRIBUTING.md §1](../CONTRIBUTING.md#1-first-time-setup) for installation and optional shared `CARGO_TARGET_DIR` setup. On macOS, Xcode Command Line Tools are required. Linux builds need the [Tauri system prerequisites](https://tauri.app/start/prerequisites/). Docker is optional: `just test-pg [version]` runs the PostgreSQL integration tests in a throwaway `postgres:<version>-alpine` container bound to 127.0.0.1 with TLS on (a throwaway CA, server and client certificates from `scripts/test-pg-certs.sh`, which needs `openssl`), removes the container and certificates on exit, and skips with exit 0 when Docker is unavailable. `just test-mysql [images…]` does the same for the MySQL/MariaDB driver (default `mysql:8.4` then `mariadb:11.4`, bound to 127.0.0.1, TLS from the images' auto-generated certificates); SQLite driver tests use temporary files and run in the normal `just test`. Docker (Docker Desktop on macOS) also runs the OpenSSH container matrix of `openrows-net`; those tests skip when Docker is unavailable, and `just test-ssh` fails instead of skipping. `ssh-keygen`, `ssh-agent` and `ssh-add` (OpenSSH client tools) generate test keys at test time. CI tooling is described in §4.

### 2.1 Common commands

```bash
just setup          # verify installed tools and enable git hooks
just fmt            # format all Rust sources
just fmt-check      # check formatting without edits
just lint           # Clippy on every workspace target, warnings are errors
just test           # cargo-nextest workspace unit tests
just test-ssh       # OpenSSH container matrix with timings (requires Docker)
just deny           # licences, advisories, bans, sources
just machete        # unused dependency scan
just hygiene        # file length and issue-linked TODO/FIXME checks
just gen-ipc        # generate bindings after changing Rust commands/types
just ipc-check      # compare generated bytes with the checked-in bindings
just gen-tokens     # regenerate packages/ui/src/tokens/tokens.css from TS
just ui-check       # token freshness and raw component colour checks
just contrast-report # WCAG ratio table for normal and high-contrast themes
just bench-ui       # production build and enforced UI CSS/JS gzip budgets
just dev            # native hidden-until-render window + Vite hot reload
just build-app      # unsigned release .app, shared CARGO_TARGET_DIR respected
just bench-startup  # ten sequential release launches, macOS GUI required
just bench-startup 20 # optional run count (minimum two)
just bench-memory   # total idle physical footprint (gate) + RSS (informational), macOS GUI required
just bench-ipc      # S1 Arrow tile round trip in release WKWebView, macOS GUI required
just bench-grid     # S2 canvas grid scroll scenarios (3 fresh launches), macOS GUI required
just bench-editor   # S5 editor keystroke-to-paint, 5 000-line SQL, macOS GUI required
just bench-test     # synthetic benchmark tests, no GUI
just script-test    # sccache guard tests with a stub sccache (§2.2)
just bench-pg-decode # Criterion decode_pg_* + gates (>= 1 M cells/s/core, first batch <= 5 ms)
just test-pg 17     # PostgreSQL integration tests in a throwaway container (skips without Docker)
just test-mysql     # MySQL 8.4 and MariaDB 11.4 integration tests in throwaway containers (skips without Docker)
just test-mysql mariadb:10.11 # any mysql:<tag> / mariadb:<tag> images, one after another
pnpm lint           # type-aware ESLint, complexity/size limits, IPC boundary
pnpm format:check   # frontend/config formatting
pnpm build          # production frontend bundle (no native window)
pnpm typecheck      # tsc --noEmit in every package
pnpm test           # Vitest + Testing Library
pnpm knip           # unused TS files, exports and dependencies
just check          # all Rust + frontend gates and binding freshness
just clean          # remove Cargo output (also affects a shared target)
just --list         # descriptions of every recipe
```

Hygiene checks tracked and new non-ignored Rust/TypeScript sources using `git ls-files`; paths containing `/generated/` are exempt from the file-length limit. Clippy thresholds are configured in `clippy.toml`, with workspace lints inherited by every crate. Generated bindings are excluded from ESLint and Prettier so the freshness test compares exact exporter bytes. Only `packages/ipc` may import `@tauri-apps/api/core`; application code calls its typed wrapper.

`just build-app` writes `release/bundle/macos/OpenRows.app` beneath `CARGO_TARGET_DIR` (or the normal Cargo target when unset). The initial window is hidden. After React commits, two animation frames schedule a paint-ready event; Rust then shows the window. The CSP and the main-window capability grant only metadata, event emission and window dragging. The build manifest declares `app_info`, generating its application permission before capabilities are compiled. No plugins are installed. The M0-T4 shell uses `@openrows/ui` tokens and displays a component gallery, with native metadata in its footer. See [07 §8](07-frontend-architecture.md#8-theming) for the implemented token pipeline.

On a Mac in a GUI session, run `just build-app`, then `just bench-startup`
(or `just bench-startup 20`) and `just bench-memory`. The harnesses build nothing
and locate the release `.app` executable using Cargo metadata, respecting
`CARGO_TARGET_DIR` and Cargo configuration. Set `OPENROWS_BENCH_EXECUTABLE` to a
release executable if using a separate build layout. Startup reports the first
launch separately and gates warm p50 ≤ 400 ms and all-runs p95 ≤ 800 ms. The memory
harness waits until first paint plus five seconds, reports app and owned WebKit
processes, and gates total physical footprint ≤ 200 decimal MB. Both save timestamped JSON in
`perf-results/` (gitignored), fail on invalid measurements or missed budgets, and
remove temporary reports while stopping each app normally with bounded signal
fallbacks. True OS-cold startup requires rebooting before the benchmark; no cache
purge is performed. These commands are not run on Linux CI. See
[13 §4](13-performance.md#4-benchmark-suite) for clock, process attribution and
required physical-footprint measurements. `just bench-test` and `just check` require no GUI.

### 2.2 sccache and sandboxed runs

With `RUSTC_WRAPPER=sccache`, every compiler call is a client that talks to one
background server over `127.0.0.1:4226` (`SCCACHE_SERVER_PORT`). The server stays alive
until `SCCACHE_IDLE_TIMEOUT` (600 s by default) passes without requests. Two
macOS Seatbelt effects make sandboxed agent runs fail with
`sccache: error: Operation not permitted (os error 1)`. Both were reproduced with
`codex sandbox -P ':workspace'` and `sandbox-exec`:

| Cause | When | Symptom |
| --- | --- | --- |
| The sandbox denies outbound network, including localhost (`network-outbound remote:*:<port>`); binding a server or a `SCCACHE_SERVER_UDS` socket is denied too | Every wrapped call inside a network-restricted sandbox | Cargo's first probe fails: `process didn't exit successfully: sccache …/clippy-driver …/rustc -vV` |
| A server spawned inside a sandbox keeps that sandbox. Later clients from other contexts reuse it while it lives | After a sandboxed run that could reach localhost but could only write its own workspace | Cacheable (non-incremental) units, such as dependencies or `CARGO_INCREMENTAL=0` builds, fail writing outputs into the caller's target: `error writing dependencies to …: Operation not permitted` |

Incremental workspace crates are not cacheable, so the client compiles them locally.
That is why the failure looks intermittent.

Fix: every recipe that compiles Rust runs through `scripts/sccache-guard.sh`. When
`RUSTC_WRAPPER` names `sccache`, the guard compiles an empty crate through the server into
the Cargo target directory. If that fails, it restarts the server from the current context
and probes again. If the server is still unreachable, it runs the command with an empty
`RUSTC_WRAPPER` (no cache) and prints a warning. Other or unset wrappers are left alone.
`just script-test` covers the guard with a stub `sccache`.

Manual recovery outside `just`: run `sccache --stop-server`, then retry the build from
the normal (unsandboxed) terminal. For network-restricted sandboxes, leave
`RUSTC_WRAPPER` unset. A restart can disturb other builds that are using the shared server
at that moment. Re-run them if they fail.

## 3. Coding conventions

### Rust

- `#![forbid(unsafe_code)]` in every crate except designated FFI crates.
- Errors: `thiserror` in libraries, typed `OdbError` at API boundaries; `anyhow` only in binaries/tests.
- Async: no blocking calls in async code (lint via `clippy::await_holding_lock` and code review); use dedicated threads for blocking drivers.
- Public APIs documented (`#![warn(missing_docs)]` in public crates).
- Logging with `tracing` spans carrying `session_id`, `query_id`, `request_id`.

### TypeScript

- Strict mode, no `any` (lint error), explicit return types on exported functions.
- Feature-sliced folders; imports across features only through `index.ts`.
- No direct `invoke` calls — only through `@openrows/ipc`.
- Components: function components, colocated CSS modules, tokens only (no hard-coded colours/spacing; lint rule).

### Commits and PRs

The full rules, with examples, live in [CONTRIBUTING.md](../CONTRIBUTING.md). Summary:

- **Conventional Commits 1.0.0** for every commit: `<type>(<scope>)!: <subject>`, header ≤ 72 characters (PR titles ≤ 66, because squash merge appends ` (#NN)`), imperative subject, no trailing period, blank line before the body. Types: `feat`, `fix`, `perf`, `refactor`, `docs`, `test`, `build`, `ci`, `style`, `chore`, `revert`. Scopes are crate/package/area names without the `openrows-` prefix.
- **Attribution:** commit messages, PR titles, PR descriptions and review comments describe the change only — no `Co-authored-by` trailers, co-author sections, signatures or "generated with/by" footers.
- **Enforcement:** `scripts/git-hooks/commit-msg` checks all of the above locally (enable once per clone with `git config core.hooksPath scripts/git-hooks`). Run the same hook on the PR title before opening a PR (`printf '%s\n' "<title>" > /tmp/t && bash scripts/git-hooks/commit-msg /tmp/t`). CI re-checks the squash commits that land on `main`.
- **Branches:** `<type>/<short-description>` (e.g. `feat/grid-column-pinning`), rebased on `main`.
- **Merging:** squash-merge only; the PR title is the squash commit header, so it must be a valid Conventional Commit header.
- Small PRs; every PR links an issue, requirement ID or ADR; UI changes include screenshots in both themes; docs updated in the same PR.
- Two approvals for changes to: security-sensitive code, FFI crates, change-set apply path, value codecs, update/signing config.
- DCO sign-off (`git commit -s`) required (see [22-governance-and-licensing.md](22-governance-and-licensing.md)).

### Files that never enter the repository

- Secrets and local environment files (`.env`, keys, certificates) — covered by `.gitignore`.
- Personal editor and tool configuration, including local AI coding assistant instruction/config files. These are excluded per developer through their global git excludes file or the clone's `.git/info/exclude`, never through tracked files. Ignore rules do not untrack files already committed, so reviewers check the PR file list for such files and ask for their removal.

## 4. CI pipeline

### 4.1 Current: minimal pipeline (private repository)

While the project is solo and private, CI uses free GitHub Actions minutes sparingly. **Local `just check` is the gate for every branch and PR**; CI is a final integration check on `main` only. [.github/workflows/ci.yml](../.github/workflows/ci.yml) runs one Ubuntu job (15-minute timeout; a newer push to `main` cancels an older run) on:

- every push to `main`, i.e. each squash-merged PR;
- manual dispatch (`gh workflow run CI --ref <branch>`), for the rare case where a branch needs a Linux check before merge.

Pull requests and pushes to feature branches do **not** trigger CI. Steps:

| Step | What it checks |
| --- | --- |
| Commit messages (push only) | Every non-merge commit pushed to `main` (the squash commit, whose header is the PR title) goes through `scripts/git-hooks/commit-msg` via `scripts/ci/check-commit-messages.sh` |
| Linux prerequisites | WebKitGTK 4.1, build-essential, curl, wget, file, libxdo, OpenSSL, Ayatana appindicator, librsvg |
| Node / pnpm | Node 24, pinned pnpm, pnpm store cache, frozen lockfile install |
| Frontend lint / format | `pnpm lint`, `pnpm format:check` |
| Frontend types / tests / dead code | `pnpm typecheck`, `pnpm test`, `pnpm knip` |
| Binding freshness | Rust `bindings_are_fresh` test (same registry as the app) |
| Format | `cargo fmt --all --check` |
| Lint | `cargo clippy --workspace --all-targets --locked -- -D warnings` |
| Tests | `cargo nextest run --workspace --locked -E 'not binary(ssh_container)'`; container-backed driver tests are `#[ignore]`d there (reported as skipped) and run locally with `just test-pg` and `just test-mysql`; the `openrows-net` SSH container matrix is filtered out in CI and runs locally in `just check` / `just test-ssh` |

Every gate, including those CI skips (cargo-deny, cargo-machete, hygiene, UI and benchmark checks), runs locally with `just check` and is mandatory before pushing a branch or opening a PR; the acceptance report carries the evidence. Actions are pinned to full commit SHAs, the workflow has read-only permissions, and checkout does not persist credentials. A red run on `main` is fixed immediately with a follow-up PR. PR-triggered CI and branch protection return with the full pipeline (§4.2) once the project has outside contributors.

### 4.2 Planned: full pipeline (when the repository goes public)

Restored when the repository is made public (the full version is preserved in the first commit of PR #5):

- Rust matrix on Ubuntu, macOS and Windows (NFR-PORT-03).
- `supply-chain` job: cargo-deny and cargo-machete.
- `hygiene` job: hygiene script, ShellCheck, actionlint.
- `ci-ok` aggregate job as the single required status check, plus branch protection on `main` (PRs only, `ci-ok` required, linear history, no force pushes).
- Dependabot for GitHub Actions and Cargo with `ci(deps)` / `build(deps)` prefixes.
- Later: frontend browser E2E, Tier 1 driver integration with containers, benchmarks against `main`, nightly matrix/fuzzing/E2E, and signed release workflows.

## 5. Branching and versioning

- Trunk-based: `main` always releasable; short-lived feature branches.
- Feature flags (compile-time Cargo features + runtime settings flags) for in-progress features.
- Semantic versioning; pre-1.0 releases `0.x.y` with `alpha`/`beta` channels.

## 6. Architecture Decision Records

- Any decision that is hard to reverse or affects multiple crates gets an ADR in `docs/adr/NNNN-title.md` using the template in [adr/README.md](adr/README.md).
- ADR status: Proposed → Accepted → (Superseded by NNNN | Deprecated).
